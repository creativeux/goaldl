ALDL → ESP32 input conditioning

Two transistors stand between the car's 12V-domain data line and the QT Py's 3.3V-only RX pin. It clamps the voltage and inverts the signal — the same two jobs the PL2303 cable's internal circuit does today, so the bytes come out identical to a serial capture.

If it won't sync check the byte mix first

A single inverting stage holds RX low between pulses. The UART reads that as a continuous break: it emits 0x00 forever, never sees a real start bit, and never syncs. The fault is invisible in the circuit and obvious in the data — so histogram a capture before touching a wire.

-invert will not rescue this. Those 0x00s are framing artifacts, not inverted data — there is no signal in them to flip, and neither is 2400 baud a workaround. Grab a minute with goaldl monitor -tcp <addr> -o out.raw and count the bytes; if 0xFE is missing entirely, add the second stage.

Where the two wires come from 12-pin ALDL connector

Measure before wiring. Key on, engine off: pin E to pin A should read a few volts and be busy (the ECM streams continuously). If it reads 0V or battery voltage steadily, re-check which pin you're on before connecting anything.

—Hookup wire, heat-shrinkStrain relief matters more than the electronics here
  • Power in the car: 12V accessory → any USB adapter → the QT Py's USB-C. USB carries power only in the deployed setup; data leaves over WiFi.
  • Optocoupler alternative (PC817 + ~1kΩ LED resistor) buys full galvanic isolation for a couple more parts — but an opto inverts, so it replaces stage 1 and still needs stage 2 behind it. Same three board pins either way.
  • An ESP32 can invert RX in UART hardware (UART_RXD_INV), which would make one stage sufficient — but CircuitPython's busio.UART does not expose it, so this build re-inverts in hardware instead.
  • The bridge firmware needs no change for any of this: it reads RX at 4800 baud and forwards bytes verbatim, warts and all.

One connector, both ALDL generations superset design

The 8192-baud ECMs (mid-'86+) use the same 12-pin shell but move data to pin M as a half-duplex request/response UART. One built cable can serve both: wire pin E and pin M, each through its own stage, to two of the S3's three UARTs — firmware selects which is live.
